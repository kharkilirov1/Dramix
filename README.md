# Dramix

**Дорамы, фильмы и сериалы — в одном Flutter-клиенте.**

Dramix объединяет каталог Kodik, поиск, выбор озвучки и серий со встроенным
плеером и личной локальной библиотекой. Избранное, списки, история и статистика
просмотра сохраняются на устройстве; отдельный аккаунт Dramix не требуется.

Проект находится в разработке. Основные целевые платформы — **Windows и Web**.
Наличие исходников платформы и успешные unit tests не означают, что каждый
сценарий воспроизведения уже проверен на реальном устройстве.

## Возможности

- **Каталог и поиск.** Дорамы, фильмы, сериалы, аниме и мультфильмы; переключение
  категории, сортировка и фильтры.
- **Карточка тайтла.** Описание, постер, год, рейтинги и доступные варианты
  озвучки; состав информации зависит от ответа Kodik.
- **Сезоны и серии.** Выбор эпизода и открытие плеера внутри приложения.
- **Личная библиотека.** Избранное и статусы «Смотрю», «В планах», «Просмотрено»,
  «Отложено» и «Брошено».
- **История.** Последние открытые серии, сохранённые checkpoints и история
  поисковых запросов.
- **Подборки и обзор.** Редакционные коллекции, популярные и недавно
  обновлённые тайтлы.
- **Профиль.** Локальная статистика библиотеки и просмотров.
- **Обработка ошибок.** Повтор запроса без потери cursor каталога и ручное
  продолжение загрузки, если клиентский фильтр отсеял несколько страниц.

Интерфейс тёмный, на русском языке. Часть расширенных фильтров относится к
экспериментальному слою Dramix Plus; реальный платёжный провайдер не подключён.

## Платформы

| Платформа | Что есть в репозитории | Основной путь воспроизведения |
|---|---|---|
| **Windows** | Нативный проект и скрипт сборки | WebView2 через `flutter_inappwebview` |
| **Web** | Web-проект Flutter | HTML `iframe`; API через CORS-прокси |
| **Android** | Нативный проект | `webview_flutter` с iframe-обёрткой |
| **iOS** | Нативный проект; свежая проверка не выполнена | `webview_flutter` с iframe-обёрткой |
| **macOS / Linux** | Отдельные платформенные проекты не добавлены | Готовая поддержка не заявляется |

Windows-версия **не использует `media_kit`**. Встроенный WebView2 — основной
путь, а не внешнее окно браузера. Плеер и доступность контента зависят от
стороннего сервиса: открытый iframe сам по себе не доказывает воспроизведение.

## Быстрый старт

### 1. Подготовьте окружение

Базовое окружение проекта — **Flutter 3.24.5 / Dart 3.5.4**. Ограничение Dart
в [`pubspec.yaml`](pubspec.yaml) — `^3.5.4`. Совместимость с более новым Flutter
проверяйте отдельно, не обновляя одновременно все зависимости.

Для Windows нужны Visual Studio с workload **Desktop development with C++**
и доступный WebView2 Runtime. Подробности: [настройка Flutter для Windows](https://docs.flutter.dev/platform-integration/windows/setup)
и [распространение WebView2 Runtime](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).
Для Web установите Chrome или Edge и Flutter SDK.

```powershell
git clone https://github.com/kharkilirov1/Dramix.git
cd Dramix
flutter --version
flutter doctor -v
flutter pub get
```

Для приватного репозитория GitHub сначала потребуется авторизация аккаунта,
которому предоставлен доступ.

### 2. Запустите приложение

**Windows**

```powershell
powershell -NoProfile -File tools/build_windows.ps1
& .\build\windows\x64\runner\Release\dramix.exe
```

Helper подготавливает NuGet CLI, необходимый Windows-плагину. Для debug-запуска
через `flutter run -d windows` NuGet должен быть доступен в `PATH`.

**Web**

```powershell
flutter run -d chrome --web-port=8321
```

Либо используйте `-d edge`. Официальная справка: [запуск Flutter Web](https://docs.flutter.dev/platform-integration/web/building).

**Android**

Подготовьте Android SDK и JDK 17 для текущего Gradle/AGP toolchain; локальный
абсолютный путь к JDK в GitHub-копии убран. Проверьте выбранную Java через
`flutter doctor -v`. Подключите устройство, убедитесь, что оно отображается в `flutter devices`,
и выберите его через `flutter run`. Установка, подпись и проверка Android/iOS
не входят в подтверждение работоспособности Windows/Web.

### 3. Проверьте подключение к каталогу

При старте приложение пытается получить и проверить токен Kodik. Если доступ
не получен, воспользуйтесь кнопкой **«Ввести свой токен»** либо откройте
**Настройки → Ввести свой токен** после успешного запуска.

В репозитории **нет действующих встроенных API-токенов**. Доступность
community-пула не гарантируется; собственный токен вводится локально, а не
публикуется в исходниках.

**Для Web:** проверка введённого токена сразу использует текущий сетевой
маршрут — по умолчанию публичный прокси. Не вводите приватный токен, пока не
выбран доверенный маршрут. Если стартовый экран не даёт войти в настройки,
задайте свой JSON-прокси в `Net.allOrigins` в [`lib/core/net.dart`](lib/core/net.dart)
**до первой Web-сборки** либо используйте нативную версию с прямым подключением.

## Сеть и токен Kodik

### Почему Web использует прокси

Нативные сборки обращаются к Kodik напрямую. В Web браузер применяет CORS,
поэтому текущая реализация по умолчанию использует JSON-прокси
`https://api.allorigins.win/get?url=`. Режим и адрес меняются в
**Настройки → Сеть**: доступны прямое подключение, оборачивающий и prefix-прокси.

**Важно:** при работе через сторонний прокси запрос к API, включая токен,
проходит через его оператора. Для собственного развёртывания используйте
доверенный маршрут и не отправляйте через публичный прокси другие credentials.
Отключение CORS-защиты браузера не является решением для выпуска приложения.

### Как устроено получение токена

[`KodikTokenStore`](lib/core/kodik_token.dart) проверяет кандидатов перед
использованием, поддерживает локальный кэш, пользовательский ввод и загрузку
community-пула. При отказе авторизации API клиент может отклонить текущий
токен и повторить подбор.

В опубликованной версии `bundledTokens` пуст. Тесты получают синтетические
кандидаты через constructor injection и не требуют настоящих токенов.
Локальные настройки хранятся через `shared_preferences`, а не в репозитории;
это не защищённое хранилище секретов.

## Сборка

### Web

```powershell
flutter build web --release
```

Результат находится в `build/web/`. Обслуживайте **всю папку** через HTTP-сервер,
не открывайте `index.html` как `file://`. Пример локальной проверки при наличии Python:

```powershell
python -m http.server 8321 --bind 127.0.0.1 --directory build/web
```

После запуска откройте `http://127.0.0.1:8321/`. Эта команда не публикует сайт
в интернете.

### Windows

```powershell
powershell -NoProfile -File tools/build_windows.ps1
```

Скрипт перенаправляет NuGet/TEMP в локальные каталоги проекта и при
необходимости скачивает NuGet CLI. Сначала он ищет SDK в
`C:\flutter_sdk\flutter`, затем использует `flutter` из `PATH`: проверьте, что
выбрана нужная версия. Также он останавливает запущенный Dramix, поэтому
сохраните текущую работу перед сборкой.

Результат: `build/windows/x64/runner/Release/`. Для переноса приложения нужна
**вся папка Release**, а не только `dramix.exe`.

Установщик собирается отдельно, при установленном Inno Setup 6:

```powershell
powershell -NoProfile -File tools/build_windows.ps1 -Installer
```

Конфигурация — [`dramix.iss`](dramix.iss); результат — в `dist_windows/`.
Сборки, локальные WebView-профили и установщики не отслеживаются Git.

## Разработка и проверки

```powershell
flutter test --no-pub
flutter analyze --no-pub
```

Последняя проверка копии для публикации — **13 октября 2026**, Flutter 3.24.5:
**112 unit/widget tests прошли**, `flutter analyze` — **без замечаний**.
Это проверка исходников, а не подтверждение live playback или готовности релиза.

Обычный прогон тестов работает с fixtures/mock HTTP и не проверяет реальный
внешний каталог. Покрыты модели, токены, локальная библиотека, фильтры,
пагинация, переключение закладок, действия поиска, checkpoints плеера и
базовое построение экранов.

Ручная сетевая проверка запускается **отдельно**:

```powershell
flutter test test/live_smoke.dart
```

Она обращается к внешнему API. Даже успешный результат не заменяет проверку
CORS в браузере и воспроизведения внутри Windows/Web-плеера. Полный checklist:
[`docs/VERIFICATION.md`](docs/VERIFICATION.md).

### Структура проекта

```text
lib/
  core/             API, токены, сеть, модели, библиотека, тема, entitlements
  ui/               Экраны, навигация, общие виджеты и платформенные плееры
  main.dart         Инициализация приложения и gate подключения

android/ ios/       Мобильные платформенные проекты
windows/ web/       Основные целевые платформенные проекты

```

При изменениях сохраняйте существующий визуальный стиль, добавляйте regression
test на исправляемую ошибку и отдельно проверяйте затронутую платформу.
Не добавляйте в commit токены, `.env`, signing keys, cookies, screenshots
личных данных или содержимое `build/`.

## Известные ограничения

- **Нет облачной синхронизации и офлайн-загрузки видео.** Библиотека локальная;
  каталог и воспроизведение требуют сети.
- **Checkpoint не равен seek.** При неизвестной позиции embed сохраняется
  прежний checkpoint той же серии. Это не гарантия для native controller,
  сообщившего позицию `0`: его значение записывается как есть. Сторонний
  iframe не сообщает приложению текущий playback time
  и не обеспечивает автоматическое продолжение с этой секунды.
- **«Расписание» — не календарь премьер.** Экран группирует недавние обновления
  каталога по дню недели; «Уведомления» показывает ленту обновлений, не push.
- **Dramix Plus — локальный прототип entitlements.** Реальный billing и серверная
  проверка кодов не подключены; этот механизм не следует считать защитой
  коммерческих прав доступа.
- **`hideWatched` требует доработки.** Уже загруженные карточки не удаляются
  автоматически при изменении истории.
- **Windows URL-навигация требует дополнительной проверки.** Защита схем
  мобильного WebView пока не перенесена полностью в WebView2.
- **Свежая end-to-end проверка Web/Windows не завершена.** Прежние локальные
  screenshots и отметки о воспроизведении намеренно не выданы за актуальный QA.

## Данные, доступ и лицензия

Dramix — сторонний клиент: он не предоставляет собственный видеокаталог и не
выдаёт прав на контент внешнего сервиса. Используйте только контент и доступ,
на которые у вас есть соответствующие права.

Исходники подготовлены без встроенных credentials и пользовательских данных.
Порядок подготовки описан в [`docs/PUBLICATION.md`](docs/PUBLICATION.md).
Лицензия на исходный код пока не выбрана; файл `LICENSE` не добавлен.
