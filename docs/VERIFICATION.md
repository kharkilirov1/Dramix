# Проверка Dramix на Windows и Web

## Воспроизводимое окружение

Исходный проект проверялся с Flutter 3.24.5 / Dart 3.5.4. Добавьте выбранный SDK
в `PATH` и запускайте команды из корня репозитория. Не переносите `.dart_tool`
между машинами или версиями SDK: создайте локальную конфигурацию через
`flutter pub get`. Не лечите проблемы SDK удалением пользовательских данных.

```powershell
flutter pub get
flutter test --no-pub
flutter analyze --no-pub
flutter build web --release --no-pub
powershell -NoProfile -File tools\build_windows.ps1
```

Последний скрипт перенаправляет NuGet/TEMP внутрь проекта и останавливает
запущенный Dramix. Не используйте его, пока приложение выполняет нужную работу.
Для Web обслуживайте свежий `build\web` локальным HTTP-сервером и проверяйте
в настоящем браузере, а не через `file://`. Не публикуйте сборку автоматически.

## Отдельные gates

1. Unit/widget tests: ошибки первой/следующей страницы и retry того же cursor;
   ограниченная автозагрузка и ручное продолжение; закладки и статусные вкладки;
   кнопка поиска и применение фильтра; ширина 320 px; сохранение checkpoint
   именно текущей серии; дни просмотра; закрытие внутреннего HTTP-клиента.
2. Fresh build: успешный exit code отдельно для Web и Windows. Старый exe или
   `main.dart.js` не доказывает работоспособность изменённых исходников.
3. Runtime: каталог, постеры, четыре вкладки, поиск кнопкой, фильтр → результаты,
   страница тайтла, выбор озвучки/серии и встроенный плеер.
4. Persistence: запрос в истории или закладка переживает закрытие и повторный
   запуск. Не очищайте существующие данные пользователя ради smoke test.
5. Playback: два снимка с изменившимся кадром/временем. Загруженный iframe или
   `onLoadStop` не равен воспроизведению. Проверку возраста, CAPTCHA, вход,
   оплату и разрешения выполняет человек; автоматизация останавливается.

Web зависит от внешнего CORS-прокси `api.allorigins.win`, Windows обращается к
API напрямую. При отказе внешней сети фиксируйте платформу, этап и ошибку:
host tests не заменяют CORS/runtime/playback witness.

## Известные границы

- Защита сохранённого checkpoint не добавляет автоматический seek внутри
  стороннего iframe: iframe пока не сообщает приложению текущую позицию.
- `hideWatched` не удаляет уже загруженные карточки при изменении истории.
- Проверка URL-схем Windows-плеера ещё не имеет parity с мобильным WebView.
- Обычный `flutter test` не запускает `test/live_smoke.dart`. Этот ручной скрипт
  обращается к внешнему API; не включайте в диагностику токены и локальные
  пользовательские данные.
