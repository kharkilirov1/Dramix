# Dramix: надёжность данных и собственный сервер

## Первый этап: клиент Kodik

- Один подбор токена на параллельные запросы.
- Поздний отказ старого токена не сбрасывает уже выбранный новый токен.
- Сетевые ошибки, таймауты, 429/5xx и некорректные ответы не считаются отзывом ключа.
- Проверка кандидата проверяет JSON ответа, а не только HTTP 200.
- Cursor следующей страницы допускается только для доверенного HTTPS API.
- Повтор при отказе авторизации ограничен одним запросом.
- Проверки выполняются на синтетических токенах через mock HTTP.

## Второй этап: идентичность произведений

Произведение, озвучка и серия имеют разные идентификаторы.
Локальные избранное, списки и личная оценка относятся к произведению.
Сохранённая позиция относится к сезону/серии с отдельным указанием варианта озвучки.
Внешние ID Kodik/Кинопоиск/IMDb/MyDramaList/Shikimori сохраняются как ссылки провайдеров.
Не объединять произведения только по одинаковому названию.
Перед миграцией создать резервную копию исходных данных и версию схемы;
сохранить старые идентификаторы как aliases. Повтор миграции идемпотентен.

## Третий этап: собственный gateway

Небольшой сервис с адаптером Kodik, timeout, ограничением нагрузки и cache каталога.
Ключи и адрес провайдера находятся в серверной конфигурации.
Web получает данные через наш API с CORS для собственных клиентов.
Браузер не передаёт credentials публичному прокси.
Gateway не обязан проксировать видеотрафик: каталог и доставка видео раздельны.
Не хранить долгоживущие прямые видеоссылки как постоянные адреса.
На старте не нужны микросервисы: один сервис и PostgreSQL достаточно.
Развёртывание и домен выбираются перед запуском инфраструктуры.

## Четвёртый этап: optional accounts и синхронизация

Гостевая локальная библиотека остаётся доступна без регистрации.
Вход импортирует гостевые данные без их удаления до подтверждения сервера.
API: сессия, произведения, избранное, статусы, личные оценки, checkpoints.
Записи содержат update timestamps и deletion tombstones.
Повторная отправка операции безопасна; очереди переживают перезапуск.
Разные аккаунты не разделяют один пользовательский cache.
Верификация email, хеширование паролей и отзыв сессий реализуются на сервере.

## Пятый этап: социальные функции

Комментарии к произведению или конкретному сезону/серии;
спойлеры, редактирование, удаление, жалобы и модерация.
Публичные профили и общие оценки отделены от частной истории.
Счётчики просмотра и завершение серий строятся по подтверждённым событиям.
Dramix Plus требует отдельной серверной проверки реальных покупок;
локальные тестовые права не считаются billing.

## Проверка

Этот план не означает, что сервер уже создан или развёрнут.
Каждый этап идёт отдельным PR с тестами и описанием миграции.
Текущее ограничение: runtime Flutter, analyzer и device playback в этой сессии недоступны.
