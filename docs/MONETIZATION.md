# Монетизация Dramix

Документ описывает **что уже работает в коде**, что нужно подключить и какова
экономика. Начну с того, что важно сказать прямо.

## 0. Юридическая реальность (прочитать до всего остального)

Dramix — клиент к **Kodik**, а Kodik раздаёт контент без лицензий правообладателей.
Из этого следуют жёсткие ограничения:

- **Google Play и App Store такое приложение не примут.** Пункт о нарушении
  авторских прав — самая частая причина отклонения и удаления. Значит встроенные
  покупки (IAP) и подписки магазинов для этого приложения **недоступны**.
- **Продавать доступ к пиратскому контенту — отдельный состав правонарушения**,
  тяжелее, чем бесплатное приложение. Именно монетизация превращает «клиент» в
  «коммерческое распространение».
- Платёжные провайдеры (ЮKassa, Stripe, эквайринг банков) при жалобе замораживают
  счёт. Это не «если», это вопрос времени.

Поэтому ниже разделены два сценария:

- **Сценарий A — этот проект как есть** (Kodik). Жизнеспособны только
  некоммерческие модели: донаты «на поддержку разработки», без продажи доступа к
  контенту.
- **Сценарий B — легальный продукт** (свой лицензированный каталог или партнёрство
  с правообладателем/агрегатором). Здесь работают все модели ниже, включая
  подписку.

Всё, что реализовано в коде, спроектировано так, чтобы работать в обоих сценариях:
это слой прав доступа (entitlements), а не слой платежей.

### Как это выглядит для пользователя

- **Бесплатно:** каталог, поиск, страница тайтла, плеер, выбор озвучки и серий,
  история на 30 записей, избранное и списки, базовый фильтр (категория, статус,
  год, сортировка).
- **Dramix Plus:** расширенные фильтры (страна, жанры, минимальный рейтинг,
  возраст, «скрыть просмотренное»), история до 200 записей.

Гейтинг сделан **мягким**: без подписки приложение остаётся полноценным плеером,
а не урезанной демкой. Это осознанно — выручка на порядок чувствительнее к
удержанию, чем к жёсткости пейволла.

### Что не подключено (и почему)

**Приём платежей.** `Premium.gateway` по умолчанию —
`UnavailablePurchaseGateway`, который честно возвращает `false`; кнопка «Оформить»
сообщает, что оплата не подключена, и ничего не списывает. Это сделано специально:
поддельная «успешная оплата» в демо-сборке опаснее отсутствия оплаты.

**Проверка кодов на сервере.** Сейчас код проверяется локально (FNV-1a от соли и
числа дней). Это **не защита**: любой, кто прочитает `premium.dart`, сгенерирует
себе бессрочный код. Для продакшена нужен сервер — см. §4.

## 2. Модель: что продавать

Главный вопрос монетизации контентного приложения — **что именно человек покупает**.
Продавать «доступ к видео» в сценарии A нельзя. Что остаётся:

| Модель | Годится в A | Годится в B | Комментарий |
|---|---|---|---|
| Подписка на функции (наш Plus) | ⚠️ только как «поддержка» | ✅ | основной вариант |
| Разовая покупка (lifetime) | ⚠️ | ✅ | лучшая конверсия, но без LTV |
| Реклама (AdMob и т.п.) | ❌ | ✅ | в A нельзя: монетизация пиратского трафика |
| Донаты (Boosty/ЮMoney/крипта) | ✅ | ✅ | единственный безопасный вариант в A |
| Партнёрские ссылки на легальные сервисы | ✅ | ✅ | «смотреть легально» → отчисления |
| B2B / white-label плеер | — | ✅ | продавать технологию, а не контент |

**Рекомендация для сценария A:** донаты + партнёрские ссылки на легальные
кинотеатры. Не продавать доступ.

**Рекомендация для сценария B:** подписка (месяц/год) + lifetime как «якорь»,
плюс бесплатный тариф с рекламой.

## 3. Тарифы и цены

Три плана уже есть в `PremiumPlan`. Обоснование цен для рынка РФ/СНГ:

| План | Цена | Логика |
|---|---|---|
| Месяц | 199 ₽ | точка входа, сравнима с одной чашкой кофе |
| Год | 1 190 ₽ | ≈ 99 ₽/мес — «выгоднее втрое», основной якорь |
| Навсегда | 2 990 ₽ | 15 месяцев окупаемости; закрывает тех, кто не терпит подписки |

Принципы, заложенные в UI:

- **Год выбран по умолчанию** (`_plan = PremiumPlan.year`) — стандартная практика,
  поднимает ARPU без навязывания.
- **Пробный период 3 дня, один раз на установку** — реально работает, хранится в
  `dramix.premium.trial`. 3 дня, а не 7: у контентного приложения решение
  принимается за один-два вечерних просмотра.
- **Lifetime — якорь.** Наличие дорогого варианта делает год визуально дешёвым.

## 4. Как подключить реальный биллинг

Слой прав уже отделён от платежей, поэтому работа сводится к одной реализации.

```dart
class StorePurchaseGateway implements PurchaseGateway {
  @override
  Future<bool> buy(PremiumPlan plan) async {
    // 1. найти ProductDetails по id плана
    // 2. запустить покупку через in_app_purchase / RuStore / Yandex
    // 3. дождаться purchaseStream, проверить чек на СВОЁМ сервере
    // 4. вернуть true только после подтверждения сервером
  }

  @override
  Future<bool> restore() async { /* восстановление покупок */ }
}

// точка включения — одна строка в main():
Premium.gateway = StorePurchaseGateway();
```

**Коды активации нужно перенести на сервер.** Минимальная схема:

1. Пользователь платит вне магазина (донат, ЮKassa, крипта).
2. Сервер выдаёт код и **хранит его** со сроком действия и признаком «использован».
3. Приложение отправляет код на `POST /redeem`; сервер возвращает подписанный
   токен прав (например, Ed25519-подпись над `{tier, until}`).
4. Приложение проверяет подпись **публичным** ключом и хранит токен.

Тогда подделать код нельзя: приватный ключ есть только у сервера. Сейчас в
`premium.dart` реализована упрощённая локальная версия — она годится для проверки
потока, но не для денег.

## 5. Воронка и метрики

Что мерить, чтобы модель жила:

```
установка
  → первый запуск каталога           (цель: > 80 %)
  → первый запуск видео              (цель: > 45 %)  ← ключевая метрика
  → возврат на 2-й день              (цель: > 25 %)
  → упёрся в платный фильтр          (цель: 10–15 %)
  → открыл пейволл                   (цель: 5–8 %)
  → активировал пробный период       (цель: 2–4 %)
  → заплатил                         (цель: 0.5–1.5 % от установок)
```

Ориентиры, на которые смотреть:

- **Конверсия в платящих** для утилит и контентных клиентов — 0.5–2 %.
  Всё выше 3 % почти всегда означает, что бесплатный тариф слишком урезан.
- **Пробный → платный** — 25–40 %. Если ниже 15 %, проблема в пейволле, а не в
  продукте.
- **Отток подписки** — здоровый месячный отток 5–8 %.
- **LTV/CAC** — цель ≥ 3. При нулевом платном трафике (сарафан) CAC ≈ 0 и модель
  окупается почти сразу.

Технически метрики сейчас **не собираются** — это следующий шаг. Точки для
встраивания: `Premium.revision` (активации), `Library.record` (просмотры),
`ensurePremium(...)` (упор в платную функцию — это и есть основной сигнал спроса).

Заметьте: вызовы `ensurePremium` уже размечены текстом причины
(«Фильтр по странам входит в Dramix Plus»), то есть при добавлении аналитики
сразу видно, **какая именно** функция конвертирует.

## 6. Этика формулировок

Отдельная строка расходов — доверие. В коде заложены правила:

- Кнопка оплаты **не притворяется работающей**: при отсутствии биллинга она прямо
  говорит об этом.
- Пробный период выдаётся один раз и это честно написано.
- Нет таймеров-давления, «осталось 3 места» и подписок с автопродлением по
  умолчанию без предупреждения.
- Платные фильтры помечены замком **до** нажатия, а не после.

Это не только этика: скрытые списания — самая частая причина возвратов и
блокировок аккаунтов разработчика.

## 7. Порядок работ

| Шаг | Что сделать | Зачем |
|---|---|---|
| 1 | Свой сервер выдачи кодов + подпись токена прав | закрывает подделку |
| 2 | Аналитика по воронке из §5 | без цифр нет решений |
| 3 | Подключить биллинг (только для сценария B) | деньги |
| 4 | A/B пейволла: год vs навсегда по умолчанию | +10–20 % к ARPU |
| 5 | Легальный источник контента | единственный путь к магазинам и IAP |

Шаги 1–2 имеют смысл в любом сценарии. Шаг 3 — только после шага 5, иначе
аккаунт разработчика и платёжный счёт под риском.
